# The world is event-sourced, the planes are data

- **Problem**: the world must run headless for agents today and show in a pixel-art client later, across three planes (cyber, Belle Epoque, space) whose goals change from run to run.
- **Decision**: `world.py` turns actions into typed events and folds them into the state; nothing else changes it. Tiles, crops, recipes, lore and the goal live in `worlds/*.yaml`; the engine knows only kinds (walkable, soil, source, gather, lore).
- **Why**: a run's log replays alone (the map travels in `Created`), so any client, text or pixel, is a projection of the same events; `schemas/events.json` is that contract. A plane is a file, so changing plane and goal between loops touches no code.
- **Where**: `hoshi7/world.py` (`apply`, `World.act`), `hoshi7/view.py` (the agents' text projection), `schemas/events.json` (regenerated by `python -m hoshi7.schema`).
